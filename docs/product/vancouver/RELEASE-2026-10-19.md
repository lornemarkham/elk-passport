## 1. Conference — the crash

**Root cause.** The two conference migrations (`20261012…`, `20261014…`)
REVOKE and grant a few UPDATE columns, but never grant `authenticated`
SELECT/INSERT/DELETE. They relied on Supabase's default privileges, which the
shared production project (`frllwwxesxbmmaadzfaf`) does not apply. Every
signed-in visit to `/conferences` reads the visitor's memberships, Postgres
answers `42501 permission denied for table passport_conference_members`, the
page throws, and the app-wide boundary shows "Something went badly wrong".
Signed-out visitors never query, which is why the page looks fine signed out.

**Evidence.** (a) Measured against production as a fresh test account on
2026-10-16 (commit 3f583e1). I could not repeat that today: signing up a
test account on production was refused from here. (b) Reproduced today on a
local GoTrue + PostgREST + Postgres stack with production's grant posture:
without the grant migration, `permission denied for table
passport_conferences` and the attack suite cannot even start; with it,
rls-attack **68/68**, arrivals-attack **33/33**. What I could not rule out
from here: whether someone has applied the grants since 16 October and a
different fault remains. Step 1 below checks that first.

**Fix.** `supabase/migrations/20261016000000_passport_conference_grants.sql`
(least privilege: exactly what the stores issue; `anon` gets nothing).
In code, `/conferences` keeps join and create open when the list fails, and
`conferences/error.tsx` keeps failures inside the conference layout.

**Smallest production fix — no deploy needed:**

1. Supabase → project `frllwwxesxbmmaadzfaf` → SQL editor:
   `select has_table_privilege('authenticated','public.passport_conference_members','select');`
   `false` = this is the crash.
2. Paste and run `20261016000000_passport_conference_grants.sql`. It is
   idempotent. Do **not** `supabase db push` (Atlas owns the migration history).
3. Open https://gohaveaday.com/conferences signed in. It should list your
   conferences. Done.

The code half (error boundary, adsb.fi fallback, map framing) ships with
the push below.

## 3. Hockey Night

**Blocker found and fixed.** `docs/product/hockey/migration.sql` had the
same defect as Conference. Its own readiness doc said it relied on
Supabase's default grants. On a stack with production's posture:
`permission denied for table passport_occasions`, 14 attacks failing,
nobody able to read their own night. It now grants `authenticated` the same
DML outright, and that also drops TRUNCATE (readiness §2.4 finding 1).
`verify.sql` checks the grant. It also no longer counts Conference's tables
as baseline: it would have said STOP on a correct database.

**Added.** The arena picker now lists Atlas places plus the curated
restaurants and bars, with addresses, and still works when Atlas is down. A
new question, "Where are we meeting?", offers 4 real meeting points within

created before this deploy don't show it.
